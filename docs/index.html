PROJECT NOTE

既存アプリのソースをもとにした紹介サイトです。実行可能なアプリの公開デモではありません。

01 / ABOUT THE PROJECT

親しみやすい世界観で、
オークションの流れを形に。

制作テーマは、あつまれ どうぶつの森のアイテムを扱うオークション。価格の単位に「ベル」を使い、やわらかな配色や状態表示で世界観を表現しています。

ユーザー・商品・入札・落札・メッセージのデータを関連づけ、取引の流れをWebアプリとして実装しています。このページでは、その機能と実装の特徴を短時間で把握できるようにまとめました。

制作の個人的な動機・開発期間は未確認のため掲載していません。

02 / FEATURES

探す。競る。取引を進める。

ソースコードで確認した、
主な機能をピックアップ。

01 / DISCOVER

欲しいアイテムを探す

商品名の部分一致検索とカテゴリ絞り込み。新旧・終了日時・最低価格・入札件数による並び替え、10件単位のページ表示に対応。

検索・並び替え
02 / EXHIBIT

画像と一緒に出品する

商品名・カテゴリ・画像・最低価格・終了日時を登録。終了日時は日数ボタンから選べて、価格未入力時は300ベルを設定します。

出品・編集・削除
03 / BID

入札の状況をつかむ

入札を登録し、商品詳細で履歴を確認。自分の入札一覧では「最高入札者」「上位入札あり」などの状態を表示します。

入札・状況一覧
04 / KEEP

気になる商品を残す

一覧の星ボタンからお気に入りを登録・解除。ログインユーザーごとに、気になる商品をまとめて確認できます。

お気に入り
05 / CLOSE

終了した商品を処理する

Shellが終了日時を過ぎた商品を抽出。最高額の入札から落札情報を作り、入札がない商品も終了状態へ更新する構成です。

終了バッチ・メール通知処理
06 / CONNECT

落札後のやり取りへ

出品・落札一覧からメッセージ画面へ。落札情報にひもづいた投稿履歴の表示・送信と、自分の投稿を削除する処理があります。

履歴・取引メッセージ

ログインにはCakePHPのフォーム認証を使用。一般利用者向けの新規登録は現在の公開許可設定に含まれません。機能紹介はコード上の確認に基づき、実行・メール配送・Cronの稼働は未検証です。

06 / ENGINEERING NOTES

コードで伝えたい、実装の工夫。

01

検索に入札件数の集計を組み合わせる

商品一覧では入札情報をLEFT JOINし、商品ごとにCOUNT。キーワード・カテゴリの条件と組み合わせ、入札のない商品も含めて取得する構成です。

AuctionController::index() ↗
02

複数の情報から、利用者に必要な状態を作る

自分の最高入札額、全体の最高額、商品終了状態、落札者を組み合わせて表示を切り替えます。出品側にも「落札なしで終了」を含む状態ラベルを用意しています。

AuctionController::bidding() ↗
03

閲覧操作から独立した、終了処理の入口

終了日時を過ぎた商品を処理するコードをShellにまとめています。ページを開く操作に依存せず、コマンドから落札情報の作成・終了状態の更新・通知を行う設計です。

AuctionShell::main() ↗
04

フレームワークの機能を、用途に合わせて使う

ORMで関連データを取得し、ユーザー名の重複や入力形式を検証。パスワードはEntityのセッターでハッシュ化し、プロフィール更新では変更可能な項目を限定しています。

User Entity / パスワードの保存処理 ↗
05

入力の手間と、世界観の両方を考える

出品時の終了日時プリセットと選択ファイル名表示、状態ごとのバッジを実装。BGMの再生設定と位置をlocalStorageに保存する処理もあります。

出品フォームのテンプレート ↗
調査範囲と、動作確認が必要な点

掲載内容はソースコードの静的調査に基づきます。この環境ではアプリを起動していません。

  • 入札の最低価格・終了日時のサーバー側検証、取引参加者のアクセス制御、CSRF設定には確認・改善が必要です。
  • 所有者確認処理には例外クラスの名前空間の不整合があります。
  • 終了バッチの排他制御・処理全体のトランザクション・メール失敗時の復旧は確認できません。
  • マイページのヘルパー呼び出しに誤記があり、プロフィール追加項目のMigrationも見当たりません。
  • 関連テストには未実装の雛形があります。品質保証・性能向上の実績は掲載していません。
